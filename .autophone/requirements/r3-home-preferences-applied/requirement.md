# R3：偏好保存后首页回填

## 需求目标

在用户保存结构化饮食偏好并返回首页后，首页读取当前 App 进程内的偏好 Store，显示一次性应用提示和持续偏好摘要。

## 基线

- 上一轮：`r2-preferences-editor`（分支 `autophone/req-r2-preferences-editor`）
- 基线来源：上一轮验收后的分支末端。本轮从 `autophone/req-r2-preferences-editor` 开出 `autophone/req-r3-home-preferences-applied`。
- R2 偏好编辑默认态已按 18 个独立 Stable ID 完成全视觉验收，保存、返回丢弃、进程内读取和冷启动复位行为已经通过回归。

## 实现范围

- 首页读取最近一次保存的饮食偏好。
- 保存完成返回首页时显示“偏好已应用”。
- 应用提示显示 1.2 秒后消失；计时器不受导航焦点切换影响，首页组件卸载时执行清理。
- 首页持续显示偏好摘要，例如 `中辣 · ¥20–35 · 不吃香菜`。
- 没有已保存偏好时，首页保持 R2 基线布局，不显示应用提示和摘要。
- 有已保存偏好时，首页头部增加 58 pt 的偏好反馈区域；推荐图同步减少 58 pt，使推荐详情、价格行、操作区和底部导航保持基线位置。
- 新增 `home.preferences.saved_notice` 和 `home.preferences.summary` 两个 Stable ID。
- 首页现有 20 个 Stable ID、推荐切换、加入购物袋、偏好入口和底部导航行为保持不变。
- 应用提示和摘要均提供稳定的 `testID`、Accessibility Label 和 Role。

## 摘要规则

首页直接使用 R2 已验收的摘要规则：

- 无忌口：`{辣度} · {预算} · 无忌口`
- 一项忌口：`{辣度} · {预算} · 不吃{选项}`
- 两项及以上：`{辣度} · {预算} · {数量} 项忌口`

## 非目标

- 不修改偏好编辑规则。
- 不跨 App 冷启动持久化偏好。
- 不根据偏好重新计算推荐结果、价格、匹配度或配送时间。
- 不接入账号或远程服务。

## 验收标准

1. `home.preferences-applied.fixture-v1` 按 22 个独立 Stable ID 完成全视觉验收；每个 Stable ID 均验证文本、完整 Frame 和适用样式属性。
2. 参考图和实际图均为 `1290×2796 PNG`，逻辑分辨率为 `430×932 pt`，禁止重采样。
3. 应用提示和摘要在各自完整 Frame 内水平、垂直对齐；设计稿与实现采用相同逻辑画布、Scale、Safe Area 和 Dynamic Type 档位。
4. 完整视觉比较同时满足全局像素阈值、局部像素阈值、Frame 容差和 22/22 独立覆盖。
5. 保存动作完成后，应用提示和摘要通过 AX 行为断言；1.2 秒后提示消失，摘要继续存在。
6. 默认态与 R2 首页基线逐节点一致，不出现应用提示或摘要。
7. 冷启动后偏好 Store 恢复默认，首页回到 R2 默认态。
8. 首页推荐切换、加入购物袋、偏好入口和底部导航行为回归通过。
9. 应用提示计时器在导航焦点变化后仍按本次保存 Revision 到期，不发生重复呈现或常驻。
