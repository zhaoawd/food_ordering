# 优惠券选择与金额明细

需求标识：`food-20261024-coupons-v1`。依赖：`food-20261024-dish-v1` 已实现真实购物车。

## 目标与入口

购物车非空时显示“优惠券”入口 `cart.coupon.entry`，进入 `/coupons`。页面支持单选优惠券、查看费用和折扣、确认后回写购物车明细。购物车为空时隐藏该入口。

## 固定规则

| 对象 | 规则 |
| --- | --- |
| save6 | 商品金额满 3200 分减 600 分 |
| save10 | 商品金额满 6000 分减 1000 分 |
| save20 | 商品金额满 10000 分减 2000 分 |
| none | 不使用优惠券 |
| 包装费 | 每份 200 分 |
| 配送费 | 非空订单固定 300 分；空订单 0 |
| 门槛金额 | 商品及规格加价合计，不含包装费、配送费 |
| 应付 | 商品合计 + 包装费 + 配送费 − 折扣；最低为 0 |

价格均以整数分计算。一单最多一张优惠券；门槛包含等于。优惠券无到期时间，不依赖当前日期。

## 页面与交互

1. 进入时复制已应用优惠券为草稿。可用区显示“不使用优惠券”和满足门槛的券；不可用区展示其余券及“还差 ¥N 可用”，不可点击、可被读屏读取原因。
2. 切换草稿只改变本页优惠和应付金额。点击“确认使用”保存并返回购物车；返回或系统返回丢弃草稿。
3. 购物车展示商品金额、包装费、配送费、优惠和应付金额。确认时再次按当前购物车数据校验；不满足条件则清除无效草稿，提示“订单金额变化，请重新选择优惠券”（`coupons.error`），保留页面。
4. 保存后购物车数量变化导致券失效，自动恢复 none，折扣归零，并显示“优惠券已失效，请重新选择”（`cart.coupon.notice`）。数量再次满足条件时不自动重选。
5. 空购物车的商品、包装费、配送费、优惠和应付均为 0；应用券恢复 none。
6. 示例订单为标准份牛肉拌饭 2 份：商品 ¥64，包装 ¥4，配送 ¥3。无券应付 ¥71；save6 应付 ¥65；save10 应付 ¥61。save20 不可用，差额为 ¥36。
7. 页面内不提供真实支付操作。

## 设计状态与验收

| 状态 | 草稿优惠券 | 优惠 | 应付 |
| --- | --- | --- | --- |
| coupons.default.fixture-v1 | none | ¥0 | ¥71 |
| coupons.selected.fixture-v1 | save6 | −¥6 | ¥65 |

两个状态初始 committed 均为 none。测试装载时必须播种两份标准份牛肉拌饭，不能仅写入展示金额。

关键 Stable ID：`coupons.option.none`、`coupons.option.save6`、`coupons.option.save10`、`coupons.unavailable.reason`、`coupons.bill.discount`、`coupons.payable`、`coupons.confirm`。购物车明细使用 `cart.summary.subtotal`、`cart.summary.packaging`、`cart.summary.delivery`、`cart.summary.discount`、`cart.summary.payable`。

验收范围包括默认明细、选券确认、不可用券、门槛相等、数量变化使券失效、取消、空购物车和确认时校验，共 8 条用例。

## 设计与实现约束

- 这是待实现需求。设计包证明结构化设计可编译，不证明 App 已实现或设备验收通过。
- 视觉真源为本功能 `states/` 下的 UI DSL、Fixture 与 Token。参考图和逐元素属性由 autophone 编译器生成。不得编辑 `packages/` 内的派生文件。
- 主验收设备为 430×932 pt、scale=3，参考 PNG 为 1290×2796 px。安全区为上 59 pt、下 37 pt；系统区域单独比较。窄屏正文可滚动，底部操作保持可见，禁止横向溢出。
- 延续 Food AI 的浅米色页面、白色卡片和红色主按钮。选中项同时用背景色和勾选标记表达；实际控件通过 accessibilityState 暴露选中或禁用状态。
- 产品实现使用 React Native / Expo Router。交互控件有稳定 testID 和可访问名称。需要视觉观测的节点接入现有 ObservedPressable、ObservedText、ObservedView，并绑定真实 sourceRef。
- 设计原型为固定状态快照。DSL 中的 interactions 只声明意图；保存、返回、校验和价格联动按本需求实现，不能把静态 HTML 当成交互实现。
- 所有数据本地提供。使用合成地址，不接地图、真实支付、优惠券服务或推荐服务。状态在本次 App 会话内保存；进程重启恢复默认，不要求跨进程持久化。
- 验收模式必须能显式加载每个 state_id 并重置应用状态。加载 Fixture 后用独立的运行时状态处理后续用户操作；不得根据用例名称返回预写结果。
- `acceptance-cases.json` 是本设计集的验收规格，不是 autophone 注册动作或 Operation 的执行脚本。导入时转换为项目支持的用例格式。
- 默认态与变更态进行逐元素视觉比较。其他行为与边界用例按预期文本、选中状态、禁用状态和业务状态验收；未提供参考图的状态不得声称已完成像素验收。
