# 菜品规格与数量

需求标识：`food-20261024-dish-v1`。依赖：无。

## 目标与入口

点击首页推荐卡标题 `home.recommendation.title`，进入 `/dish-detail?dishId=beef-bowl-001`。该标题保留文字观测节点，在外层新增可点击入口 `home.recommendation.details`，可访问名称为“查看炙烤牛肉拌饭规格”。

本轮只支持炙烤牛肉拌饭；该推荐卡显示时提供规格入口。其他菜品不展示此入口，避免传入不存在的菜品 ID。无效 dishId 显示“菜品不存在”和“返回首页”，不得创建购物车记录。

## 固定数据与计算

| 对象 | 值 |
| --- | --- |
| 菜品基础价 | 3200 分 |
| 标准份 / 大份 | +0 / +600 分 |
| 加蛋 / 豆腐 / 蔬菜 | +300 / +400 / +500 分，可多选 |
| 数量 | 整数 1–9，默认 1 |
| 合计 | (基础价 + 份量加价 + 所有加料加价) × 数量 |

所有计算使用整数分，展示为人民币。定制例：大份、加蛋、2 份，(3200+600+300)×2=8200 分，显示 ¥82。

## 页面与交互

1. 页面展示菜名、基础价、份量、加料、数量和商品合计。选项或数量变化后立即重算合计。
2. 数量为 1 时减号禁用；数量为 9 时加号禁用。禁用控件使用 #77655F 文本色及 #F3ECE6 背景色，并暴露 disabled 状态。
3. 点击“加入购物车”后，一次加入所选数量。操作过程中按钮禁用；成功后返回首页。返回未提交时不改变购物车。
4. 商品、份量和加料 ID 集合均相同则合并行数量；加料顺序不影响匹配。不同份量或不同加料形成独立行。单行数量最多 9；若合并后超限，不修改购物车，并显示“同一规格最多 9 份”（`dish.cart.error`）。
5. 复用 `store/cart.store.ts` 的状态管理。必须统一处理首页角标、实际商品行与数量；不得仅更新首页局部 cartCount。必要时扩展一次加入 N 份和合并上限的原子操作。
6. 首页购物车按钮 `home.header.cart` 跳转 `/cart`。扩展当前空购物车页面，展示真实商品行、规格摘要、数量、商品合计和“继续选购”（返回首页）。删除最后一行后回到原空态。“订单”入口本轮仍指向 `/cart`。
7. 为使本功能能够独立交付，首页既有“立即下单”保持加入购物车语义；对当前推荐加入标准份、不加料、1 份，并与上述购物车状态共用计算。
8. 底部固定操作区在小屏可见，正文可滚动。商品行 Stable ID 使用菜品 ID 和规范化规格键，不使用数组下标。

## 设计状态与验收

| 状态 | 配置 | 期望 |
| --- | --- | --- |
| dish.default.fixture-v1 | standard、[]、1；购物车初始为空 | 合计 ¥32，减号禁用 |
| dish.customized.fixture-v1 | large、[egg]、2；购物车初始为空 | 合计 ¥82 |

默认态中的减号以设计 Token 生成禁用视觉，实际禁用行为需由组件实现。关键 Stable ID：`dish.portion.*`、`dish.extras.*`、`dish.quantity.*`、`dish.total`、`dish.add`。新增购物车汇总使用 `cart.summary.quantity`、`cart.summary.subtotal`；行身份规则见实现约束第 8 条。

验收范围包括默认态、价格联动、数量上下限、提交联动、相同规格合并与超限、不同规格分行及取消，共 6 条用例。无效 dishId 作为第 7 条用例。
